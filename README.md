# 帧序 · 本地视频增强工作台

Windows x64 桌面程序，使用 Electron 独立窗口运行。视频、模型推理和编码都在本机完成，无需浏览器或开发服务器。

## 启动

双击根目录的 `启动帧序.cmd`，或运行 `desktop-release` 里版本号最大的 `FrameSequence-*-Windows.exe`。便携版已经包含 Python、FFmpeg/FFprobe、Real-ESRGAN、RIFE 和模型，使用时无需另装 Node.js、Python 或 FFmpeg。

也可运行 `desktop-release/win-unpacked/FrameSequence.exe`，必须保留整个 `win-unpacked` 目录。单文件便携版会先解压运行时，首次启动需要等待，并需要临时磁盘空间。AI 推理需要支持 Vulkan 的显卡及正常驱动；普通转换可使用 CPU 编码。当前构建未签名。

## 使用

1. 点击「添加视频」、按 Ctrl+O，或把多个视频拖到列表。
2. 在右侧统一配置，所有视频共用同一套设置，不再有单视频独立参数。
3. 选择输出目录，点击「开始处理」，队列按顺序逐项运行。
4. 完成后通过行内按钮打开输出位置；失败、取消或中断的任务可以重试。

支持普通缩放、Real-ESRGAN 动漫画质增强、RIFE 提帧，输出 H.264/H.265 MP4。支持保持原始、720p、1080p、2K、4K 和自定义偶数尺寸，支持原始帧率或 24/30/60/120 fps。保持比例时，预设尺寸是容纳画面的范围，竖屏会交换预设方向；例如 4:3 素材选择 720p，实际输出为 960×720。

## 两组独立设置

**处理策略**只影响 AI 画面处理：速度优先根据目标尺寸确定超分输入，选择足够的 2×/3×/4×倍率；质量优先保留原始输入后超分，再匹配目标尺寸。普通缩放无需选择该策略。AI 使用现有动漫模型，不保证所有实拍素材都获得主观画质提升。

选择「自定义」时可调整：超分分块 tile、超分线程 `-j`（加载:处理:保存，默认「自动」即 `1:2:2`）、每块帧数、中间片段画质（无损 / 高 CRF 12 / 中 CRF 18）。自定义沿用速度优先的输入规划，只改变这些调参项；较高的 tile 和线程数在显存较小的显卡上可能更慢或失败。

**输出控制**决定最终压缩：

- 固定码率：填写视频 Mbps，平均值允许波动，音频和封装另占体积；分辨率建议范围仅供参考。
- 动态码率：填写质量目标，建议 18～28，可从 23 开始；数值越小通常画质越高、文件越大。硬件使用 CQ，软件使用 CRF，不同编码器的相同数字不代表相同效果。
- 体积限制：填写每分钟最多 MB。按“总时长 ÷ 60 × MB × 1,000,000”限制整个文件，包含音频和封装。此模式使用软件编码，最多尝试三次最终压缩；预算不足或最终超限会明确失败。

处理策略不会修改上述输出参数，也不直接决定文件体积。以 720p→1080p 为例：速度优先为 540p→AI 2×→1080p；质量优先为原始 720p→AI 2×到 1440p→缩到 1080p。720p→4K 可直接使用 3×模型。超过单次模型倍率时组合多次超分；不会先把源画面普通放大来充当模型输入，也不会在 AI 尺寸不足时静默普通放大。两种策略在部分大倍率场景会采用相同路径。

降低目标帧率时，先完成丢帧，再对保留帧进行 AI 增强。每块处理完的画面先编成 libx264、yuv420p 的中间片段（默认 CRF 12，接近视觉无损但仍是有损），全部完成后拼接再做最终压缩，因此画面会经历两次有损编码。中间片段体积随视频时长累积。

## 队列和文件

运行中的任务在名称列显示进度条和百分比，操作列切换为暂停与删除。行内「暂停」冻结当前任务的处理进程，保留当前进度；点击「继续」沿用同一任务处理，不重新推理。暂停期间仍占用显存和缓存，下一项等待。行内删除先停止任务并清理临时文件，再移出列表；源视频及已完成成片保留，队列继续后续任务。等待项和已完成项也可在其他任务运行时移出。

「暂停后续」在当前任务完成后暂停；「取消当前」取消当前任务并继续后续；「停止队列」停止当前与待处理任务。已提交的任务保存配置快照，后续修改不会影响它们。重启后保留视频、设置和完成记录，未完成任务（包括暂停项）标为中断，可重试，暂不支持退出后的推理断点续算。

默认不覆盖源视频。同名输出可自动编号或跳过；正式成片在完整解码和参数检查后发布。任务记录位于 `%APPDATA%/帧序/queue-v1.json`，AI 缓存默认位于程序所在目录下的 `framesequence/<任务 ID>`（便携版为 exe 所在文件夹，开发时为项目根目录）；该目录不可写（例如安装在 Program Files）时退回系统临时目录。可在设置面板的「缓存目录」改到其他盘（所选目录下同样建立 `framesequence/<任务 ID>`）。AI 使用 PNG 分块处理，每块完成后编成 libx264 中间片段并删除 PNG；片段会保留到最终压缩结束，长视频缓存仍会随时长累积，请预留磁盘空间。开始 AI 推理前会估算所需空间，缓存盘不足时立即失败并提示。每个阶段（抽帧、超分、补帧、分段编码）的耗时在 AI 阶段结束时随进度事件的 `stageSeconds` 字段给出，界面暂不显示。

## 当前支持边界

- 第一版面向 Windows 10/11 x64。NVENC 通过短帧实测后启用，不可用时尝试对应的软件编码器，实际编码器显示在任务行内。
- 普通输出直接复制兼容的第一条 AAC 音轨；其他音频或体积限制模式转为 AAC 192 kbps，也可关闭音频。暂不保留字幕流、其他音轨、章节与附件。
- 变帧率视频转为恒定帧率；当前暂不处理 HDR、高于 8 位的画面和非方形像素视频，会在提交时提示原因。
- 当前实测机器为 NVIDIA T1200 Laptop 4GB，已验证短片处理。尚未完成 RTX 4060、其他全新电脑、长视频耐久与长视频缓存峰值测试。

节点方案见 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)，逐节点结果见 [ACCEPTANCE.md](ACCEPTANCE.md)。开发、构建与自动验收命令见 [frontend/README.md](frontend/README.md)。第三方许可证随包放在 `resources/runtime/licenses`，Electron 许可证在程序目录内。

## 从源码运行与仓库结构

仓库保留当前桌面版源代码、必要模型与 GPU 工具。旧网页、旧命令行脚本、过时说明和未使用模型已清理，历史版本可从 Git 提交记录恢复。依赖、运行时缓存、测试成片与打包产物不进入 Git。

开发环境安装 Node.js、Python 3.13 和 FFmpeg/FFprobe，并确保 Python、FFmpeg/FFprobe 在 PATH 中，然后执行：

```powershell
cd frontend
npm ci
npm start
```

- `frontend/src/`：桌面界面与导出配置。
- `frontend/desktop/`：Electron 窗口、文件访问、队列、打包与验收脚本。
- `processing/`：实际视频处理、AI 超分与补帧、输出编码。
- `models/`：当前使用的 Real-ESRGAN animevideov3 2×/3×/4×模型。
- `rife-ncnn-vulkan-20221029-windows/`：RIFE 工具与 v4.6 模型。

打包命令及逐节点验收方式见 [frontend/README.md](frontend/README.md)。

本轮改动与进一步优化分析见 [OPTIMIZATION.md](OPTIMIZATION.md)。
